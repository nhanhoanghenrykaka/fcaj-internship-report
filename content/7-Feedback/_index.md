### Overall Evaluation

**1. Learning environment and community**  
What I appreciated most is that FCAJ gave each learning activity a concrete output. The Worklog showed progress, the Proposal required architecture reasoning, Blogs pushed deeper investigation, and the Workshop required repeatable implementation steps.

**2. Support from mentors / team admin**  
Through program materials and sharing sessions, I gained practical perspectives on AWS, DevOps, system design, and solution building. I learned best when I received a direction or troubleshooting approach and then worked through the issue myself.

**3. Relevance to my learning direction**  
Shopsflow helped connect my programming background with cloud infrastructure. I needed to understand networking, databases, IAM, monitoring, deployment, and cost in addition to application code.

**4. Learning and skill-development opportunities**  
I improved at requirement analysis, drawing request paths, technical writing, and layer-by-layer troubleshooting. Blogs and Event reports also helped me explain technical topics in my own words.

**5. Events and community activities**  
The 13/6 meetup broadened my view of DevOps, Data Analytics, AWS Community, and real working environments. The 25/7 Agentic AI Build Week event changed how I reviewed Shopsflow by focusing on problem, value, architecture, cost, and demo quality.

**6. Hugo website report format**  
At first, Hugo and Markdown added extra setup work. After getting familiar with the structure, I found the website format suitable for technical reporting because sections, Workshops, Blogs, Events, and live resources can be linked clearly.

### Additional Questions

- **What satisfied me most:** I can now explain the main Shopsflow request flow instead of only recognizing AWS service names.
- **What I still need to improve:** IaC, CI/CD, production security, advanced monitoring, and load testing.
- **Would I recommend FCAJ:** yes, especially for students who want hands-on AWS learning and are willing to read documentation and debug independently.

### Suggestions & Expectations

* Add periodic **Architecture Reviews** for requirements, request paths, security boundaries, failure points, and cost drivers.
* Add **Troubleshooting Labs** with prepared failures such as unhealthy ALB targets, ECS image-pull failures, RDS SG issues, or missing NAT routes.
* Include a short **Cost Checkpoint** in each Workshop.
* Add a follow-up track on **Terraform/CDK and CI/CD** after Console-based labs.
* Organize **mini demos / architecture clinics** for students to present problem, solution, architecture, and lessons learned.

My next learning goals are Infrastructure as Code, CI/CD for ECS, security hardening, observability, and load testing. I also want to explore Agentic AI on AWS with clearer architecture, monitoring, security, and cost control.
